# 部署手册

当前生产服务器：`SERVER_IP`

## 线上架构

```text
浏览器
  |
  v
Nginx :80
  |-- /        Astro 主页
  |-- /blog/   Astro 博客与文章
  |-- /ai/     Agent 前端代理
  |-- /api/    Agent API 代理
  `-- /vendor/ Agent 自托管前端依赖
                  |
                  v
             127.0.0.1:7860
             blog-rag-agent
```

公网入口：

- `http://SERVER_IP/`
- `http://SERVER_IP/blog/`
- `http://SERVER_IP/ai/`

Agent 的 Docker 端口只绑定 `127.0.0.1:7860`，公网不能直接访问 7860。

## 服务器路径

| 路径 | 用途 |
| --- | --- |
| `/usr/share/nginx/html` | Astro 静态生产文件 |
| `/etc/nginx/default.d/zh-kinger.conf` | 静态路由与 Agent 反向代理 |
| `/root/blog-rag` | Agent 源码、Compose 和持久化数据 |
| `/root/blog-rag/.env` | 生产密钥，只保存在服务器 |
| `/root/blog-rag/data` | Chroma、SQLite、反馈等运行数据 |

首次统一站点部署前的 Nginx 默认页备份位于：

```text
/usr/share/nginx/html.bak-before-zh-kinger-20260724
```

## 前端构建

```bash
cd astro-site
npm ci
npm run build
```

构建输出位于 `astro-site/dist/`。构建必须完成全部文章页面后才能上传。

## Agent 部署

真实配置从 `rag-server/.env.example` 创建：

```bash
cd rag-server
cp .env.example .env
```

只在 `.env` 中填写真实密钥，不要把它写进代码、Markdown、Dockerfile 或 Compose。

服务器更新：

```bash
cd /root/blog-rag
docker compose up -d --build
docker compose ps
```

## Nginx 验证

每次修改配置后先测试，再重载：

```bash
nginx -t
systemctl reload nginx
```

健康检查：

```bash
curl -I http://127.0.0.1/
curl -I http://127.0.0.1/blog/
curl -I http://127.0.0.1/ai/
docker inspect blog-rag-agent --format '{{.State.Health.Status}}'
```

## 防火墙

公网仅需要：

- TCP 80：当前 HTTP 网站
- TCP 443：配置证书后启用
- TCP 22：建议只允许管理员固定公网 IP

不要向公网开放 7860、3306、33060 或内部管理端口。服务器 `firewalld` 已放行 HTTP，7860 已从公开端口列表移除。

## HTTPS 待办

当前为 HTTP。绑定正式域名后，应配置 TLS 证书、开放 443，并将 80 永久重定向到 443。

## 常用运维

```bash
cd /root/blog-rag
docker compose logs -f
docker compose restart
docker compose ps
```

静态站点和 Agent 数据分开管理：服务器是运行与部署目标，Git 远程仓库才是源码和文档的长期版本库。
