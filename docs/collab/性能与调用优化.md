# LLM 调用性能与优化(为什么慢 · 怎么解决 · 如何取舍)

> 场景:M2 检索链 + M3 评测跑一次耗时数分钟到十几分钟。本文拆解**时间花在哪、怎么提速、提速的代价**,并定下"用评测验证提速不掉分"的纪律。

---

## 1. 现象
- 单次评测(10 题)耗时数分钟~十几分钟。
- 单个用户提问也有明显延迟(尤其"重排"阶段)。

## 2. 为什么慢 —— 时间几乎全在**串行的 LLM 网络往返**

一次评测 10 题,每题的 GLM API 调用次数:

| 环节 | 调用次数/题 | 说明 |
|---|---|---|
| **重排 llm_rerank** | **~20** | pointwise:对 RRF 融合后 `fetch_k=20` 个候选**逐个**打分,一候选一次调用,且**串行** |
| 生成答案 | 1 | |
| 评测判官 | ~3 | faithfulness + answer_relevancy + context_recall |
| 不接地题联网 | +2~3 | 搜索 + web 作答 |
| **单题合计** | **~24** | |

**× 10 题 ≈ 240 次 GLM 调用,串行**,每次一个到 MaaS 端点的网络往返(1~3s)→ 累积数分钟~十几分钟。
> 真实用户单次提问只有"~20 重排 + 1 生成",没有 3 个判官(那是评测专属)。

## 3. 瓶颈定位:**pointwise 重排(占 ~200/240 次调用)**
- 根因:`llm_rerank` 逐个候选打分 = `fetch_k` 次独立调用,还串行。
- 关思考(`enable_thinking=False`)已把单次从 ~5.5s 降到 ~1s(见 notes 2026-07-13),但**次数太多**仍是主瓶颈。
- auditor 早先也标注过此项(顺序调用、无并发/缓存/超时)。

## 4. 解决办法(可叠加,按性价比排序)

| 手段 | 效果 | 代价/风险 |
|---|---|---|
| **① listwise 重排** | 20 次 → **1 次**(一次调用给全部候选打分)| 需模型稳定输出可解析的分数列表;校准可能略逊 pointwise |
| **② 只排 RRF top-N** | `fetch_k=20` → `rerank_candidates=10`,再省一半 | 若某相关块被 RRF 排在 11–20,会被截掉(RRF top-10 通常已含) |
| **③ 并发调用** | 串行→并行,墙上时间 ~/N | 调用数不变;需线程/异步;注意 MaaS 限流 |
| **④ 查询/结果缓存** | 重复 query 零调用 | 需失效策略;RAG 精准场景语义缓存慎用(旧答案风险) |
| **⑤ 关思考** ✅已做 | 单次 5.5s→~1s | 仅判断类任务用,生成保留思考 |

**本轮采用 ①+②(listwise + top-N)**:重排从 ~20 次/题 降到 **1 次/题**(≈20x),`rerank_candidates` 作 config 旋钮。③并发作为后续可选加速。

## 5. 优化取舍(核心原则:提速可能掉精度,必须用评测验证)

- **speed ↔ precision**:pointwise 逐个专注打分,校准最细;listwise 一次排全部,快但可能略糙。截候选(top-N)提速但有漏排风险。
- **不能拍脑袋换**:M2 先做"对"(pointwise),提速留到 M3 有评测之后——因为现在有 `hit@k / MRR / faithfulness / answer_relevancy`,可以**改完一测,证明"分不掉"才采纳**。
- **失败降级**:重排整体失败时,不能静默把所有题判成"不接地"(会误走联网/通用);应**退化为 RRF 序并给及格分**(信任 RRF),并告警(修 auditor 标注的降级隐患)。

## 6. 决策与验证闭环
1. 实现 listwise 重排 + `rerank_candidates=10`(config)。
2. 跑评测对比 **pointwise 版 vs listwise 版**:
   - 期望:总耗时大幅下降;`hit@k / MRR / faithfulness` **不掉**(在误差内)。
   - 若某指标明显下降 → 调 `rerank_candidates` 或回退 pointwise。
3. 结果记入 `notes.md`,CSV 归档 `data/eval_results.csv`。

> 基线参考(pointwise+联网,n=10):hit@k 1.0 / mrr 0.929 / faithfulness 0.992 / answer_relevancy 0.98 / context_recall 1.0。listwise 版需对齐或不劣于此。
