# ADR-0007: 评测栈 —— 自实现 metrics(弃 RAGAS)
- 状态: 已采纳(取代 plan/项目总结中"RAGAS"的原计划)
- 日期: 2026-07-13
- 相关模块: M3

## 背景(为什么要做这个决策)
"极致精准"需评测驱动开发:每次改动量化对比。原计划用 RAGAS(RAG 专用 4 指标 + Langfuse 集成)。落地时发现兼容问题,须重估。

## 选项(≥2,每个一句话)
- **A RAGAS**:成熟 RAG 评测框架,四指标开箱。
- **B 自实现 metrics.py**:GLM 判官算 faithfulness/answer_relevancy/context_recall + 纯算 hit@k/mrr。
- **C DeepEval / TruLens**:pytest 断言式 / 内联反馈。

## 优劣对比
| 方案 | 优 | 劣 |
|---|---|---|
| A RAGAS | 开箱四指标、社区成熟 | **RAGAS 0.4 硬 import 已删的 vertexai 路径,与本栈 langchain 1.x 不兼容**;依赖重(datasets>=4/pyarrow);collections 轨道需 GLM 稳支持 function-calling(未证实) |
| **B 自实现** | 零重依赖、与本栈契合、判官关思考省时、逻辑透明、hit@k/mrr 精确按 doc_id | 需自己写指标 + 判官 prompt |
| C DeepEval/TruLens | CI 回归 / 内联反馈 | 非当前需求,过度 |

## 结论(选了哪个)
选 **B:自实现 `metrics.py`**——GLM 判官(faithfulness/answer_relevancy/context_recall)+ 纯算 hit@k/mrr;golden.jsonl(10 题四档)+ run_eval.py。给 `answer` 追加返回 retrieved_doc_ids/contexts 供评测复用(免重复检索)。首版基线量化了缺口(GB200 web faithfulness=0.0、手册作者 refuse 缺分流),直接指引 M4/M5。

## 为什么不选替代
- **不选 RAGAS**:R6 判定"轨道 A 大概率可行",但实测 0.4 版硬 import community 已删的 vertexai 路径,与 langchain 1.x 冲突,装配即坑;且 Hit@k/MRR 它本就不提供(须自算)、依赖重、collections 轨道依赖 GLM function-calling(未证实)。自实现规避全部不确定性,且指标口径完全可控(hit@k 按项目 doc_id 对齐 `_dedupe_by_doc`)。
- **不选 DeepEval/TruLens**:定位是 CI 断言/内联反馈,当前只需出分调参,引入是过度。

## 回溯条件(什么情况下该重估)
RAGAS 修复兼容 + 需其独有指标;或需 CI 回归门禁(可加 DeepEval);Langfuse 在 M6 有 UI 流量后可选接入做在线追踪。
