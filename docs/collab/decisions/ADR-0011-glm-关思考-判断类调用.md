# ADR-0011: 判断类调用关闭 GLM 思考
- 状态: 已采纳
- 日期: 2026-07-13
- 相关模块: M2 / M5

## 背景(为什么要做这个决策)
GLM-5.2 是推理模型,默认带"思考"。分类/打分/路由这类判断任务调用它时,非流式大输入会长时间"空想"(表现为卡死),且延迟高、结果可能因"想太多"漂移。需定何时开/关思考。

## 选项(≥2,每个一句话)
- **A 全程开思考**:所有调用都保留推理。
- **B 判断类关思考、生成类保留**:按任务类型分。

## 优劣对比
| 方案 | 优 | 劣 |
|---|---|---|
| A 全程开 | 无需区分 | 判断类 5.5s(268 字思考),延迟高;非流式大输入会长时间空想=卡死;温度外的额外不确定性 |
| **B 分类型** | 判断类 5.5s→~1s、更确定(temp=0+无思考不漂);生成类保留思考保质量 | 需按调用点区分配置 |

## 结论(选了哪个)
选 **B**:判断类调用(route_question / grade_documents / grounding_gate / 重排打分 / 评测判官)默认 `extra_body={"enable_thinking": False}`(或 `thinking={"type":"disabled"}`)+ temp=0;对话生成保留思考。实测判断类从 5.5s 降到 ~1s、结果不变。配套:凡 LLM 调用需重试 + 韧性(MaaS 流式偶发 `WinError 10054` 断连)。

## 为什么不选替代
- **不选全程开思考**:判断类任务要的是快 + 确定,思考不仅无收益(结果不变)还带来两个实害——延迟高 5x + 非流式大输入长时间空想被误判"卡死",并给 temp=0 之外引入"想太多"的漂移。生成类才需要思考换质量,故按任务类型分而非一刀切。

## 回溯条件(什么情况下该重估)
某判断任务关思考后准确率下降(需权衡开思考换质量);GLM 端点思考行为/参数变化。
