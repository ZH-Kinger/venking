# ADR-0013: 路由形态(混合式 Adaptive-RAG)与加固(确定性预筛 + LLM)
- 状态: 已采纳
- 日期: 2026-07-14
- 相关模块: M5

## 背景(为什么要做这个决策)
M5 要决定"问题进来先干什么":博客技术问题走接地 RAG(带引用),代码/闲聊/菜谱走通用模式(不接地)。路由放哪、怎么分,决定整张图的骨架、速度和误判风险。且实测发现:纯 LLM 路由在 temp=0 下仍会飘(GLM MaaS 非严格确定),"红烧肉"这类边界问题偶发被误判成 rag。

## 选项(≥2,每个一句话)
- A 一律先检索再判:不做前置路由,任何问题都检索,靠接地分决定。
- B 纯路由优先:完全靠路由把问题分到 rag/general/web/refuse 各走各的。
- C 混合式 Adaptive-RAG(选中):前置廉价路由分 general/rag 两桶,rag 再走"检索→接地闸门→改写→联网→弃答"阶梯,web/refuse 由运行时结果涌现。
- 路由加固子选项:C1 纯 LLM few-shot / C2 确定性预筛+LLM(选中) / C3 embedding 语义路由 / C4 多次投票。

## 优劣对比
| 方案 | 优 | 劣 |
|---|---|---|
| A 先检索再判 | KB 问题永不误路由;最稳 | 闲聊/菜谱也白检索 ~8s;分不清 general 与 refuse |
| B 纯路由优先 | 最快 | 路由一旦误判(KB 问题判 general)直接丢引用、精准塌方,无第二道防线 |
| C 混合式(选中) | 快路径省检索 + 接地闸门仍是第二道防线;web/refuse 不靠预测更稳 | 前置多一次分类调用(已用关思考压到 ~1s) |
| C1 纯 LLM | 简单 | temp=0 仍飘,红烧肉偶发误判 |
| C2 预筛+LLM(选中) | 防御纵深:无歧义非技术先确定性拦截,稳且省一次 LLM | 预筛词表要维护 |
| C3 embedding 路由 | 稳、快 | 要调阈值、备原型集,多一套机制 |
| C4 多次投票 | 最稳 | 3x 调用+延迟,违背"快路径"初衷 |

## 结论(选了哪个)
路由形态选 **C 混合式 Adaptive-RAG**;路由加固选 **C2 确定性快路径预筛 + LLM few-shot 兜后**。预筛只拦无歧义非技术问题(寒暄/菜谱/写作),必须高精度(拿不准返回 None 交 LLM),绝不把技术问题误判成通用。

## 为什么不选替代
- 不选 A:菜谱/闲聊白花 ~8s 检索,且无法产出"通用回答"这一档(会把常识问题也硬塞进接地契约)。
- 不选 B:与"精准第一"冲突——路由误判 = 直接丢引用,没有兜底;而路由是概率组件必然有误判。
- 不选 C1:实测红烧肉在 temp=0 仍偶发飘到 rag,单靠 few-shot 不够稳。
- 不选 C3/C4:单用户右尺寸下,embedding 路由多一套阈值机制、投票 3x 成本,收益不抵复杂度;预筛已能以极低成本消除主要误判。

## 回溯条件(什么情况下该重估)
- 预筛词表频繁误伤技术问题,或漏放大量通用问题 → 升级到 C3 embedding 语义路由。
- 出现多类目(不止 general/rag)需要分流 → 重估为更细的 route。
